Fine-Tuning LLMs with LoRA:
A Practical Guide

The Problem with Full Fine-Tuning

Suppose you want to fine-tune LLaMA-3-8B on your own domain-specific dataset — medical notes, legal documents, customer support transcripts. Full fine-tuning updates every one of the model's 8 billion parameters on each training step. To do that in 16-bit precision, you need roughly 16 GB just to hold the weights, plus another 48 GB+ for gradients and the Adam optimiser states. That's an A100 or better. Not exactly accessible.

Parameter-efficient fine-tuning (PEFT) is the umbrella term for techniques that achieve comparable results while touching only a small fraction of the total parameters. LoRA — Low-Rank Adaptation — is currently the most widely used PEFT method, and for good reason.

📊
Numbers at a glance: Full fine-tuning a 7B model updates ~7 billion parameters. A LoRA adapter with rank r=16 typically adds ~4–8 million trainable parameters — around 0.1% of the original model. The VRAM requirement drops from 80 GB+ to under 10 GB.

What LoRA Actually Does

The key insight behind LoRA is a hypothesis about the intrinsic dimensionality of fine-tuning: the weight updates needed to adapt a pretrained model to a new task are actually low-rank. You don't need to change all the weights — you only need to learn a small delta that lives in a low-dimensional subspace.

Formally, for a pretrained weight matrix W₀ ∈ ℝ^(d×k), LoRA freezes W₀ and adds a trainable decomposition:

W = W₀ + ΔW = W₀ + B · A

where A ∈ ℝ^(r×k), B ∈ ℝ^(d×r), r ≪ min(d, k)

A is initialised with random Gaussian values; B is initialised to zero so that ΔW = 0 at the start of training (preserving the pretrained behaviour). Only A and B are updated by the optimiser.

During inference, you can fold the adapter back into the original weights (W = W₀ + BA) with no added latency — this is a key advantage over adapter layers, which add extra computation at inference time.

The rank r controls the capacity of the adapter. Typical values range from 4 to 64. Higher rank = more expressiveness = more VRAM + longer training. For most tasks, r=8 or r=16 is a solid starting point.

QLoRA: 4-bit Quantisation + LoRA

QLoRA, introduced by Dettmers et al. (2023), pushes memory efficiency further by quantising the frozen base model weights to 4-bit NormalFloat (NF4), a data type optimised for normally distributed weights. The LoRA adapters themselves remain in 16-bit and are trained normally.

⚡
With QLoRA you can fine-tune a 13B model on a single 24 GB consumer GPU (e.g. an RTX 3090) — something that would have required a full A100 cluster just two years ago.

QLoRA also introduces double quantisation (quantising the quantisation constants themselves) and paged optimisers (using CPU RAM as overflow when GPU memory spikes). Both are handled automatically by the bitsandbytes library.

Setup: PEFT + Transformers

The Hugging Face ecosystem makes LoRA surprisingly straightforward. You need three libraries: transformers, peft, and bitsandbytes (for QLoRA).

bash install 
pip install transformers peft bitsandbytes accelerate datasets trl

Load the base model in 4-bit for QLoRA:

python load_model.py 
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig

MODEL_ID = "meta-llama/Meta-Llama-3-8B"

# 4-bit quantisation config (QLoRA)
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",          # NormalFloat4 — best for LLM weights
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,     # double quantisation saves ~0.5 GB
)

model = AutoModelForCausalLM.from_pretrained(
    MODEL_ID,
    quantization_config=bnb_config,
    device_map="auto",
    trust_remote_code=True,
)
tokenizer = AutoTokenizer.from_pretrained(MODEL_ID)
tokenizer.pad_token = tokenizer.eos_token  # LLaMA has no pad token by default

Key Hyperparameters Explained

python lora_config.py 
from peft import LoraConfig, get_peft_model, TaskType

lora_config = LoraConfig(
    r=16,                        # Rank — start here, increase if underfitting
    lora_alpha=32,               # Scaling factor: effective LR = alpha/r * LR
    target_modules=[             # Which weight matrices to adapt
        "q_proj", "k_proj",
        "v_proj", "o_proj",
        "gate_proj", "up_proj", "down_proj",
    ],
    lora_dropout=0.05,           # Small dropout on adapter weights
    bias="none",                 # Don't train biases — saves parameters
    task_type=TaskType.CAUSAL_LM,
)

model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# Trainable params: 6,553,600 || All params: 8,037,699,584 || Trainable%: 0.082%
r
Rank

Controls adapter capacity. r=4 is very efficient; r=64 approaches full fine-tuning quality. For most instruction-following tasks, r=8–16 is optimal. Doubling r roughly doubles VRAM and training time.

α
lora_alpha

Scales the adapter output: ΔW = (alpha/r) · BA. Setting alpha = 2r is a common default. Think of it as controlling how much the adapter can shift the original weights.

mod
target_modules

Which layers to apply LoRA to. Applying to all attention projections and the MLP gates (gate_proj, up_proj, down_proj) generally gives better results than attention-only, at a modest VRAM cost.

Training Loop

Using the trl library's SFTTrainer (Supervised Fine-Tuning Trainer) is the fastest path to a working training loop:

python train.py 
from transformers import TrainingArguments
from trl import SFTTrainer
from datasets import load_dataset

dataset = load_dataset("json", data_files="your_dataset.jsonl", split="train")

training_args = TrainingArguments(
    output_dir="./lora-llama3-output",
    num_train_epochs=3,
    per_device_train_batch_size=2,
    gradient_accumulation_steps=4,   # effective batch = 2×4 = 8
    learning_rate=2e-4,
    lr_scheduler_type="cosine",
    warmup_ratio=0.05,
    fp16=False,
    bf16=True,                        # bfloat16 is better on Ampere+ GPUs
    logging_steps=10,
    save_strategy="epoch",
    optim="paged_adamw_8bit",         # QLoRA's memory-efficient optimiser
    report_to="none",
)

trainer = SFTTrainer(
    model=model,
    tokenizer=tokenizer,
    train_dataset=dataset,
    dataset_text_field="text",        # column in your dataset that has the text
    max_seq_length=2048,
    args=training_args,
    peft_config=lora_config,
)

trainer.train()
trainer.model.save_pretrained("./lora-adapter")

Common Pitfalls

⚠️
Forgetting to set the pad token — LLaMA-based models have no default padding token. If you don't set tokenizer.pad_token = tokenizer.eos_token, the trainer will crash or silently produce garbage gradients on batched inputs.
  • Learning rate too high: LoRA adapters are sensitive. Start at 2e-4 and lower to 1e-4 if loss diverges in the first epoch.
  • Dataset format mismatch: SFTTrainer expects a "text" column with the full formatted prompt+completion. Wrap your data in the model's chat template before training.
  • Merging at the wrong time: Only merge the adapter into base weights for deployment. During development, keep them separate — you can swap adapters without reloading the 8B base model.
  • Evaluating on the training set: Use a held-out eval set and compute perplexity or task-specific metrics (ROUGE, accuracy) — not just training loss.

Results and Evaluation

After training, merge the adapter and run inference:

python inference.py 
from peft import PeftModel

# Load base model (can be quantised or full precision)
base_model = AutoModelForCausalLM.from_pretrained(MODEL_ID, device_map="auto")

# Load and merge adapter
model = PeftModel.from_pretrained(base_model, "./lora-adapter")
model = model.merge_and_unload()   # fold BA into W0 — zero latency overhead

# Inference
inputs = tokenizer("Summarise this document:", return_tensors="pt").to("cuda")
outputs = model.generate(**inputs, max_new_tokens=256, do_sample=False)
print(tokenizer.decode(outputs[0], skip_special_tokens=True))

For task-specific evaluation, the lm-evaluation-harness library by EleutherAI benchmarks fine-tuned models on standard academic tasks. For RAG or instruction-following, RAGAS or custom human eval rubrics are more informative than perplexity alone.
